# Polyplaces Frontend — Security & Usability Fix Spec

Audience: an implementation model/agent making these fixes. Follow each task exactly.
Scope: this repository only (static frontend deployed via Cloudflare Workers static
assets — see `wrangler.toml`). Tasks marked **[BACKEND]** cannot be completed here;
record them, do not attempt them.

General rules:

- Do not reformat files or change anything not listed here.
- After editing `assets/js/app.js` or any HTML file, run `npm run bust` to refresh
  the `?v=` cache-bust hashes.
- Do not commit unless asked. Never run `git push`.

## P0 — Critical security

### P0-1: Security headers are not applied in production

**Problem:** All security headers (CSP, HSTS, X-Frame-Options, etc.) live in
[.htaccess](.htaccess), which only works on Apache. The site is deployed as
Cloudflare Workers static assets (`wrangler.toml` → `[assets] directory = "."`),
where `.htaccess` is ignored — production serves **no security headers at all**.

**Fix:** Create a file named `_headers` at the repo root with this exact content:

```
/*
  X-Frame-Options: SAMEORIGIN
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Strict-Transport-Security: max-age=31536000; includeSubDomains
  Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()
  Content-Security-Policy: default-src 'self'; script-src 'self' https://unpkg.com https://plausible.io; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com https://unpkg.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' https://*.tile.openstreetmap.org data:; connect-src 'self' https://api.polyplaces.co.uk https://nominatim.openstreetmap.org https://plausible.io https://*.ingest.sentry.io https://*.ingest.de.sentry.io; object-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'self' https://api.polyplaces.co.uk; upgrade-insecure-requests

/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

Notes:
- This CSP intentionally drops `https://browser.sentry-cdn.com` — see P1-2, which
  self-hosts Sentry. Do P1-2 in the same change, otherwise Sentry breaks.
- CSP has no `'unsafe-inline'` in `script-src`, so P0-4 (inline contact script)
  MUST be done in the same change, otherwise the contact form breaks.
- Keep `.htaccess` unchanged (harmless; covers any future Apache deploy).

**Acceptance:** `_headers` exists at repo root; `npx wrangler deploy --dry-run`
succeeds; after deploy, `curl -sI https://polyplaces.co.uk/` shows the CSP header.

### P0-2: Repo internals may be publicly served (`.git`, `.htaccess`, `scripts/`)

**Problem:** `[assets] directory = "."` uploads the whole repo. `.assetsignore`
excludes some files but not `.git/`, `.htaccess`, `scripts/`, or `wrangler.toml`.
If `.git/` is uploaded, the entire source history — including `.env` — is
downloadable from the live site (e.g. `/.git/config`).

**Fix:** Replace [.assetsignore](.assetsignore) content with:

```
.git/
.gitignore
.assetsignore
.claude/
.vscode/
node_modules/
scripts/
.env
.env.example
.htaccess
composer.json
package.json
package-lock.json
wrangler.toml
*.md
```

**Acceptance:** after deploy, `https://polyplaces.co.uk/.git/config`,
`/.htaccess`, `/scripts/generate-env.js`, and `/config-endpoint-spec.md` all
return 404.

### P0-3: `.gitignore` deleted; `.env` and `node_modules/` are tracked in git

**Problem:** Commit `3b18cb1 "remove gitignore"` deleted `.gitignore`. `.env` and
all of `node_modules/` are now committed. `.env` currently holds only public URLs,
but the pattern guarantees a future secret gets committed, and `node_modules`
bloats the repo.

**Fix:**
1. Create `.gitignore` at repo root:
   ```
   node_modules/
   .env
   assets/js/env.js
   .wrangler/
   ```
   (`assets/js/env.js` is generated by `scripts/generate-env.js`; keep the file on
   disk for now since HTML references it — just stop tracking future changes if it
   is regenerated with new values. If it must stay deployable, remove that line and
   leave env.js tracked.)
   **Decision:** keep `assets/js/env.js` tracked (it is deployed as an asset).
   Final `.gitignore`:
   ```
   node_modules/
   .env
   .wrangler/
   ```
2. Untrack without deleting local files:
   ```
   git rm -r --cached node_modules
   git rm --cached .env
   ```
3. Do NOT rewrite history. Add a note to the commit message that `.env` past
   values should be rotated if they ever contained secrets.

**Acceptance:** `git status` shows `.gitignore` added, `node_modules` and `.env`
staged as deleted from index; files still exist on disk.

### P0-4: Inline `<script>` on contact page will be blocked by CSP

**Problem:** [contact/index.html:118-175](contact/index.html:118) contains the
whole contact-form handler inline. The CSP in P0-1 (`script-src 'self'`) blocks
inline scripts — the form would silently stop working.

**Fix:**
1. Create `assets/js/contact.js` containing exactly the JS currently inside the
   inline `<script>…</script>` block (the IIFE, unchanged, plus the P2-1 email
   validation change below).
2. In `contact/index.html`, replace the inline block with:
   ```html
   <script defer src="../assets/js/contact.js"></script>
   ```
   Place it after the `env.js` script tag so `window.__POLYPLACES_ENV__` exists.
3. Add `'assets/js/contact.js'` to the `ASSETS` array in
   [scripts/bust-cache.js:18](scripts/bust-cache.js:18), then run `npm run bust`.

**Acceptance:** no `<script>` tag without a `src` attribute remains in any HTML
file (JSON-LD `<script type="application/ld+json">` in `index.html` is fine —
CSP does not block it). Contact form still submits.

## P1 — High security

### P1-1: XSS sinks — API/cache data injected into `innerHTML` unescaped

**Problem:** In [assets/js/app.js](assets/js/app.js), `renderSizeOptions()`
(lines ~221–321) builds HTML with template literals using unescaped values from
the products API **and from a localStorage cache** (`polyplaces_store_cache_v1`),
which any other flaw or a shared machine can poison: `product.name`,
`product.displaySize`, `meta.badge`, `frame.priceId`, `frame.colourHex`,
`frame.colourName`, `frame.unitAmount`. A malicious `colourHex` like
`"><img src=x onerror=alert(1)>` executes script.

**Fix:** in `assets/js/app.js`:
1. `escapeHtml()` already exists (line ~1234). Move its definition above
   `renderSizeOptions` (or leave it — function declarations hoist; verify it is a
   `function` declaration, not an expression. It is — no move needed).
2. In `renderSizeOptions()`, wrap every interpolated dynamic value in
   `escapeHtml(...)`: `product.name`, `product.displaySize`, `product.id` (in the
   `id=`/`name=`/`for=` attributes), `frame.priceId`, `frame.colourName`.
3. Validate `colourHex` instead of escaping (it goes into a `style` attribute):
   ```js
   const safeHex = /^#[0-9a-fA-F]{3,8}$/.test(frame.colourHex) ? frame.colourHex : '#cccccc';
   ```
   and use `safeHex` in the `style="background-color:..."` interpolation.
4. In `_applyFramePrices()` (line ~434), tighten validation: require
   `typeof f.priceId === 'string'`, `typeof f.colourName === 'string'`,
   `typeof f.colourHex === 'string'` and the same hex regex; drop entries that fail.
5. In `loadProducts()` / `sanitizeProductList()`, additionally coerce/validate:
   keep only products where `typeof product.id === 'string'`,
   `typeof product.name === 'string'`, and `typeof product.priceId === 'string'`.

**Acceptance:** manually set
`localStorage.polyplaces_store_cache_v1 = JSON.stringify({ts: Date.now(), products: [{id:'x', name:'<img src=x onerror=window.__pwned=1>', priceId:'p', unitAmount:100}], framePrices: null})`,
load `/store/`, confirm `window.__pwned` is undefined and the name renders as
literal text.

### P1-2: Third-party scripts without SRI; Sentry loaded from CDN

**Problem:** Leaflet (unpkg) and Sentry (sentry-cdn) load with no
`integrity` attribute — a CDN compromise = full site compromise on a payments
site. Also, `package.json` declares `@sentry/browser ^10.51.0` but pages load
CDN bundle `8.40.0` — version drift, dependency unused.

**Fix:**
1. Leaflet — add SRI (official hashes from leafletjs.com for 1.9.4) in
   `index.html` and `store/index.html`:
   ```html
   <link rel="stylesheet" href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css"
     integrity="sha256-p4NxAoJBhIIN+hmNHrzRCf9tD/miZyoHS5obTRR9BMY=" crossorigin=""/>
   <script defer src="https://unpkg.com/leaflet@1.9.4/dist/leaflet.js"
     integrity="sha256-20nQCchB9co0qIjJZRGuk2/Z9VM+kNiyxNV1lvTlZBo=" crossorigin=""></script>
   ```
2. Sentry — self-host instead of CDN:
   - Download `https://browser.sentry-cdn.com/8.40.0/bundle.min.js` and save as
     `assets/js/sentry.bundle.min.js`.
   - In ALL html files (`index.html`, `404.html`, `about/`, `care/`, `contact/`,
     `faq/`, `privacy/`, `shipping/`, `store/`, `terms/` index.html), replace the
     sentry-cdn `<script>` tag with:
     ```html
     <script defer src="/assets/js/sentry.bundle.min.js"></script>
     ```
   - Remove `@sentry/browser` from `package.json` `dependencies` (unused).
3. Confirm the P0-1 CSP has no `browser.sentry-cdn.com` (it doesn't — keep it out).

**Acceptance:** grep shows no `browser.sentry-cdn.com` in any HTML; both leaflet
tags carry `integrity`; store page map still loads.

### P1-3: **[BACKEND]** Checkout trusts client-supplied prices

**Problem:** `checkoutCart()` ([assets/js/app.js:1408](assets/js/app.js:1408))
POSTs the entire cart item objects — including client-computed `price`,
`unitAmount`-derived values, and `priceId` — to `/api/checkout`. Anyone can edit
localStorage and buy a Large for £1 if the backend uses these numbers.

**Frontend fix (do now):** in `checkoutCart()`, map cart items to a minimal
payload instead of spreading everything:
```js
items: cart.map((item) => ({
  priceId: item.priceId,
  productId: item.productId,
  bbox: item.bbox,
  center: item.center,
  rotation: item.rotation,
  zoom: item.zoom,
  location: item.location,
  customLabel: item.customLabel,
  ...(item.frame && item.framePriceId ? { framePriceId: item.framePriceId } : {}),
  ...(item.productId === 'custom'
    ? { customWidthMm: item.customWidthMm, customHeightMm: item.customHeightMm }
    : {}),
})),
```
**Backend requirement (record in `config-endpoint-spec.md` or backend tracker):**
server MUST derive all amounts from Stripe `priceId`s (and compute custom-size
price server-side from `customWidthMm`/`customHeightMm`), and MUST reject unknown
priceIds. Never read a `price` field from the request.

**Acceptance:** checkout request body contains no `price`, `unitAmount`, or
`frameUnitAmount` fields. Checkout still works against the live API (verify the
backend does not require the removed fields before shipping this — if it does,
ship the backend change first).

## P2 — Usability / correctness

### P2-1: Contact form accepts invalid email

**Problem:** [contact/index.html:76](contact/index.html:76) sets `novalidate`
and the JS only checks non-empty, so `email = "hello"` submits fine — the
customer then never gets a reply.

**Fix (in the new `assets/js/contact.js` from P0-4):** after the empty check add:
```js
var emailInput = document.getElementById('email');
if (!emailInput.checkValidity() || !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
  showStatus('error', 'Please enter a valid email address.');
  emailInput.focus();
  return;
}
```

**Acceptance:** submitting with email `foo` shows the error and does not fetch.

### P2-2: Broken footer deep link `?scale=medium`

**Problem:** Footer on every page links `A4` to `/store/?scale=medium`, but the
preselect matcher ([assets/js/app.js:518-521](assets/js/app.js:518)) matches on
product *name* ("small", "a4", "large") — `medium` matches nothing, so the link
silently falls back to the default product.

**Fix:**
1. In every HTML footer, change `href="/store/?scale=medium"` to
   `href="/store/?scale=a4"` (files: `index.html`, `404.html`, and each
   `*/index.html`).
2. Harden the matcher in `app.js` to also match on id:
   ```js
   const _preselect = _scaleParam && products.find(
     (p) => p.id?.toLowerCase() === _scaleParam.toLowerCase() ||
            p.name?.toLowerCase().replace(/\s+/g, '') === _scaleParam.toLowerCase()
   );
   ```

**Acceptance:** `/store/?scale=a4` preselects the A4 product.

### P2-3: Zooming out silently deletes the user's frame selection

**Problem:** [assets/js/app.js:756-761](assets/js/app.js:756) — on `zoomend`
below zoom 12, `clearFrame()` wipes the placed frame with no explanation. User
loses their carefully placed selection and doesn't know why.

**Fix:** keep the behaviour (frames are meaningless when zoomed far out) but tell
the user. After `clearFrame()` inside that handler, add:
```js
document.getElementById('map-hint').textContent =
  'Zoom back in to place your frame — selections clear below street level.';
```
Also do NOT clear the selected product/size (verify `clearFrame` doesn't — it
doesn't; only `clearMap` does). No other change.

**Acceptance:** zoom out past level 12 with a frame placed → frame clears and the
hint text explains why.

### P2-4: "Name it" label leaks into subsequent cart items

**Problem:** `addSelectionToCart()` ([assets/js/app.js:1329](assets/js/app.js:1329))
reads `#custom-location-label` but never clears it, so the next item added
silently inherits the previous item's personal label.

**Fix:** at the end of `addSelectionToCart()` (after `renderCart()`):
```js
const labelInput = document.getElementById('custom-location-label');
if (labelInput) labelInput.value = '';
```

**Acceptance:** add item with label "Home", then add second item — second cart
entry has no custom label.

### P2-5: Size options not keyboard-accessible

**Problem:** `renderSizeOptions()` creates size options as `<div>` with
`onclick` — no keyboard focus, no role. Keyboard and screen-reader users cannot
pick a size at all (core purchase flow).

**Fix:** in `renderSizeOptions()` (both the product loop and the custom option):
- add `btn.setAttribute('role', 'button')`, `btn.setAttribute('tabindex', '0')`,
  and `btn.setAttribute('aria-pressed', 'false')` on creation;
- in `selectProduct()`, when toggling the `active` class, also set
  `aria-pressed` `'true'`/`'false'` accordingly;
- add a keydown handler next to each `onclick`:
  ```js
  btn.addEventListener('keydown', (e) => {
    if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); btn.click(); }
  });
  ```

**Acceptance:** on `/store/`, Tab reaches each size option; Enter/Space selects it.

### P2-6: Stale price cache can break checkout for up to 1 hour

**Problem:** products (with Stripe `priceId`s) are cached in localStorage for 1
hour ([assets/js/app.js:1440-1442](assets/js/app.js:1440), `_STORE_CACHE_KEY`
TTL check at line ~463). If prices rotate in Stripe, users checkout with dead
priceIds and get an opaque failure.

**Fix:** reduce both TTLs to 5 minutes:
```js
const _PRODUCTS_CACHE_TTL = 300000; // 5 minutes
```
(the same constant is used for both caches — one-line change). Additionally, in
`checkoutCart()`'s catch block, when the server responds non-OK, clear the store
cache so a retry refetches fresh priceIds:
```js
try { localStorage.removeItem(_STORE_CACHE_KEY); localStorage.removeItem(_PRODUCTS_CACHE_KEY); } catch {}
```

**Acceptance:** constant updated; failed checkout clears both cache keys.

### P2-7: Oversized inline SVG on store page

**Problem:** [store/index.html:167](store/index.html:167) — the "Free delivery"
icon has `width="800px" height="800px"` and hardcoded `fill="#000000"`, unlike
its sibling icons. If CSS ever fails to constrain it, it renders 800px tall.

**Fix:** remove the `width`, `height`, and `fill` attributes from that `<svg>`
tag (keep `viewBox="0 0 50 50"` and the xmlns attributes).

**Acceptance:** icon renders at same size as siblings; no `800px` in the file.

### P2-8: Cookie banner is homepage-only and "Reject" does nothing

**Problem:** the cookie notice exists only on `index.html` (line ~315), yet
Plausible analytics loads on every page, and clicking "Reject" still loads
Plausible on subsequent pages. Misleading consent UX (Plausible is cookieless,
but the banner promises a choice it doesn't honour).

**Fix (minimal, frontend-only):** honour the choice by gating Plausible. In
every HTML file that has the Plausible tag, replace:
```html
<script defer data-domain="polyplaces.co.uk" src="https://plausible.io/js/script.js"></script>
```
with a small external loader `assets/js/analytics.js` (new file, add to
bust-cache ASSETS):
```js
(function () {
  if (localStorage.getItem('pp_cn') === '0') return;
  var s = document.createElement('script');
  s.defer = true;
  s.dataset.domain = 'polyplaces.co.uk';
  s.src = 'https://plausible.io/js/script.js';
  document.head.appendChild(s);
}());
```
referenced as `<script defer src="/assets/js/analytics.js"></script>`.
(Do NOT inline it — CSP from P0-1 blocks inline scripts.)

**Acceptance:** with `localStorage.pp_cn = '0'`, no request to `plausible.io` on
any page; with `'1'` or unset, Plausible loads.

### P2-9: Forged URL can wipe a user's cart

**Problem:** `showCheckoutBanner()` ([assets/js/app.js:183-186](assets/js/app.js:183))
clears the cart whenever `?checkout=success` is in the URL — anyone can send a
victim `https://polyplaces.co.uk/?checkout=success` and empty their cart. Low
impact (annoyance), but free to tighten.

**Fix:** only treat success as real when Stripe's session id is present:
```js
if (status === 'success' && params.get('session_id')) {
  clearCart();
}
```
**[BACKEND]** requirement: set the Stripe Checkout `success_url` to include
`&session_id={CHECKOUT_SESSION_ID}`. Until that lands, keep the old behaviour —
so implement as: clear cart if `session_id` present OR (temporarily) always on
success, controlled by a single `const REQUIRE_SESSION_ID = false;` flag near the
function, defaulting to `false`, flipped to `true` once the backend adds the
param. Add a `TODO(backend): flip after success_url includes session_id`.

**Acceptance:** flag exists; behaviour unchanged until flag flipped.

## P3 — Hygiene

### P3-1: Delete stray mirrored asset

`assets/imgs/polyplaces.co.uk/assets/js/app.js%3Fv=d12b7ad8` is an accidentally
committed crawl artifact — an old copy of `app.js` served publicly. Delete the
whole `assets/imgs/polyplaces.co.uk/` directory (`git rm -r`).

### P3-2: Remove `composer.json`

There is no PHP in this project; `composer.json` only echoes deploy timestamps.
Delete it (it is also in `.assetsignore`, but dead files invite confusion).

### P3-3: Sentry DSN in `config-endpoint-spec.md`

The spec file hardcodes the production Sentry DSN and calls it a "secret". A DSN
is not truly secret, but the file shouldn't set that precedent: replace the DSN
value in both places in the file with `<SENTRY_DSN — from backend env>`, and fix
the wording "including secrets that must not be stored in the git repository" →
"including environment-specific values that should not be hardcoded in the
frontend repository".

### P3-4: X-XSS-Protection header

`.htaccess` sets `X-XSS-Protection: 1; mode=block` — deprecated and can introduce
issues in old browsers. Do not carry it into `_headers` (P0-1 already omits it).
Optionally delete lines 16-17 from `.htaccess`.

2. P0-4 + P2-1 (externalize contact script + email validation).
3. P1-2 (self-host Sentry, SRI for Leaflet).

7. P2-2 … P2-9, then P3.
